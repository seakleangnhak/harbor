## Security, compatibility and operating boundary

Focused source review and regression tests found no confirmed authentication
bypass, premature publication or critical data-loss defect in tested scope.
Owner sessions remain hashed server-side, seven-day expiry, HttpOnly
SameSite=Strict cookie, current-password-verified rotation/session revocation,
same-origin mutation guards, bounded requests and process-local login throttle.
Encryption keys and Telegram credentials never enter Git, build arguments or
public logs. Initial allowlisted 382-file current-source scan and reachable-history
Gitleaks 8.30.1 scan report zero findings; final expanded scan is pending.

Metadata remains plaintext in protected SQLite. Host/root trust, key protection,
external Telegram account/channel durability and independent encrypted content
copies remain operator responsibilities. No independent security certification,
public-internet deployment or external penetration test is asserted.

Completed v1.2.1 storage geometry/envelopes remain compatible. Finish/cancel jobs,
stop the sole application and verify offline encrypted backups before upgrade.
Rollback uses matching old configuration and a verified pre-upgrade archive in a
fresh volume. Preserve newer references separately; old snapshots omit new files.
Never downgrade against live pending queue state, reinitialize a bound drive,
delete volumes or run copied MTProto authorizations concurrently.

## Remaining limitations and approval

- Live cross-DC placement/retrieval, physical Safari/iOS, multi-day operation, power loss and provider durability remain NOT TESTED.
- A cold tiny range authenticates one full 100 MiB envelope; cache thrash can add I/O. Live browser PDF/video cold/seek performance remains NOT TESTED. Chromium MOV is unsupported in test distribution; WebKit MOV and both engines' WebM play/seek pass.
- No hard persistent-volume quota, automatic remote garbage collection, metadata repair, in-place key rotation or automatic off-host backup exists.
- Missing browser input still requires original-file reselection. Queued accepted bytes can restart; final publication still requires completion/verification. Backups omit unfinished parts/cache.
- Docker AMD64 runtime uses emulation here. No physical AMD64 host or physical iOS claim. New GitHub Actions/GHCR execution remains NOT TESTED.

Publication requires separate owner approval for the audited source push and
successful exact-commit main CI, then approved stable annotated `v1.3.0` tag and
GHCR multiarch publication. Existing tags must remain immutable. Repository or
package visibility changes and Dokploy deployment are separate approvals. No
approval is inferred from a local PASS. Final readiness decision is pending.
