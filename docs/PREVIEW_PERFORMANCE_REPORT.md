# Preview performance — Milestone B

Date: 2026-10-22. Scope: reader/cache implementation and isolated generated fixtures. **PASS for the reproduced boundary regression and focused cache correctness/race checks.** These checks do not qualify real browser PDF/video latency, live Telegram performance, or the complete 768 MiB mixed workload. Those results belong to the coordinator's integrated qualification.

## Implemented change

`chunkReader.Read` prematurely discarded its authenticated buffer whenever a read reached a storage-chunk boundary or EOF. The HTTP download handler authenticates one byte before sending headers, then `http.ServeContent` seeks back to send the requested content. When that byte is the last byte of a chunk, the same reader fetched and decrypted the chunk twice. A cached read avoided the second remote fetch but still repeated full-chunk authentication/decryption.

The fix removes the three-line eager discard. A reader retains its current authenticated chunk until another chunk replaces it or `Close` releases it. There is still at most one plaintext chunk per open reader, with the existing transfer-slot admission bound. `Close` clears the plaintext reference and releases the slot. Retention can extend the buffer's lifetime between reaching EOF and closing the reader; source-copy and mixed-workload memory qualification must account for that lifetime.

`TestPreviewPreflightRetainsAuthenticatedBoundaryChunk` reproduces both an intermediate chunk boundary and EOF using exact generated bytes. The frozen baseline fails with two backend Gets at both positions; the fixed reader passes with one Get and asserts that closing releases its buffer and slot. No storage format, queue bound, worker count, encryption policy, or frontend behavior changes.

No production cache rewrite or plaintext preview derivative was added. Conditional/invalid-range HTTP optimizations and browser qualification are separate coordinator/QA integration work.

## Cold-read ceiling and cache behavior

HD01 authenticates one complete AES-256-GCM envelope per storage chunk. A cold small range therefore requires the entire containing chunk, up to 100 MiB of plaintext plus 32 envelope bytes. Chunk identity, length and SHA-256 must verify before its plaintext can be served. Seeking directly into unauthenticated ciphertext would violate this guarantee. A smaller final chunk costs its actual size, not a padded 100 MiB.

The ciphertext cache remains two entries / 256 MiB including in-flight reservations. Every hit still authenticates and verifies its own private plaintext buffer. Same-key concurrent misses coalesce; canceled leaders allow surviving readers to retry. Unpinned LRU entries are evicted, disk-write failures fall back safely, corrupt entries are refetched and verified, and final file verification bypasses the cache. Restart deliberately discards recognized disposable ciphertext; unknown files and symlinks are refused. No plaintext preview is persisted.

The existing cache benefits repeated same-chunk reads but does not shorten the first remote fetch. Requests whose working set exceeds two chunks can pay fill/eviction cost without reducing remote reads. Separately encrypted derivatives could address some cold previews, but require a proven source association, recovery, invalidation and deletion lifecycle; they were not introduced without that evidence.

## Repeated-range and eviction cross-check

The existing repeated-range benchmark opens a new reader for each of four 256 KiB same-chunk ranges and adds 20 ms per adapter Get. Each sequence starts with an empty application cache. The eviction benchmark reads chunk sequence `0,1,2,0` from three 100 MiB chunks with no injected delay. The differing delays mean the two workloads cannot be compared against each other. Both use a local generated fixture, not Telegram, HTTP, PDF.js or a media player.

Same-chunk cache reuse avoids 75% of Gets/returned ciphertext, with 8.35% lower synthetic sample median elapsed. Three of four reads reuse cached ciphertext, but each reader still authenticates/decrypts the full chunk, so cumulative allocation remains about 400 MiB. The cold eviction sequence saves no remote fetch and adds 52.67% sample median elapsed. Sample coefficients of variation: repeated cache-off 1.42%, repeated cache-on 2.71%, eviction cache-off 0.08%, eviction cache-on 12.48%. With three samples, p95 is just the maximum.

These fresh results preserve Milestone A's conclusion: cache is useful for locality and costly under thrash. Historical live same-chunk results in [CACHE_QUALIFICATION.md](CACHE_QUALIFICATION.md) remain historical evidence, not a new Milestone B live measurement. Do not raise cache limits or concurrency based on these synthetic timings.
