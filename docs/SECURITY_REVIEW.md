# Phase 2 security review

Date: 2026-10-21. Scope: Harbor authentication, diagnostics, encrypted chunk handling, MTProto session/channel safeguards, and recovery boundaries. Source review plus generated local fixtures; no personal data, actual `.env`, real session, or live Telegram service was accessed by the security agent. This is a focused qualification, not an exhaustive penetration test.

## Result

**PASS for reviewed controls and exercised live qualification.** Coordinator verified real QR authorization, intended-channel resolution, small/multipart Telegram roundtrips, retrieval after restart, and live browser upload/preview/verified download. All six tracked remote qualification chunks passed the ciphertext/nonce probe. Source review and synthetic safeguards pass. After an additional idle-process SIGKILL and persisted-session restart, all five published qualification fixtures retained exact SHA-256. No new concrete security defect was found in the final QR/login/download-routing review; this does not imply exhaustive coverage.

## Changes

- Authenticated diagnostics now return `storage_connection` with only allowlisted `state`, optional `last_checked_at`, and numeric `retry_count`. Configuration alone never implies an active Telegram connection. An absent callback reports `local` for the local adapter and `unknown` otherwise.
- Internal API errors keep generic HTTP responses and now log only the fixed `internal` classification. Arbitrary provider/error strings cannot disclose embedded credentials, requests, invite links, or session details through this path.
- Regression checks cover every unauthenticated file/folder mutation, HEAD content, diagnostics callback isolation, unknown-state redaction, synthetic-secret error redaction, and removal of temporary metadata snapshots after successful backup.

## Remaining boundaries

- The host OS and owner account are trusted. Anyone with that authority can read content keys and Telegram sessions; permissions isolate other local accounts, not the owner.
- Filenames, MIME type, sizes and plaintext hashes remain in owner-only SQLite. Telegram receives opaque document names plus encrypted bytes, but can observe channel/message membership, encrypted sizes and timing.
- Auto-delete and channel permissions are checked during connection setup. Later changes can remove remote chunks; downloads fail integrity/availability checks rather than reconstruct missing data.
- A process crash between successful remote blob creation and SQLite reference commit can leave an orphan encrypted message. No broad Telegram cleanup is performed. Recovery or garbage collection must remain restricted to tracked Harbor objects.
- Loopback HTTP is intended for local use. Non-loopback hosting requires HTTPS and secure cookies. Existing Compose binding remains loopback-only.
- Live identity and restart persistence are now supported by coordinator evidence. Forced transport/flood-wait behavior remains synthetic; no account-restriction stress test is attempted. Live cross-DC retrieval and container authorization are not inferred from host same-DC success.
