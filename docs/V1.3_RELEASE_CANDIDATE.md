## Local build and evaluation

```sh
docker build --build-arg GO_TAGS=telegram \
  --build-arg HARBOR_VERSION=1.3.0-rc.1 \
  --build-arg SOURCE_DATE_EPOCH=0 -t harbor:1.3.0-rc.1 .

python3 scripts/ci_check.py docker-smoke \
  --image harbor:1.3.0-rc.1 --platform linux/arm64 --version 1.3.0-rc.1
```

These are local image names, not pullable GHCR artifacts. Build without runtime
configuration or secrets. Smoke creates disposable local-adapter data, checks
browser onboarding/lockout, auth/CSRF, 100 MiB multipart/SHA/ranges and persistent
restart/recreation, then removes only its own containers/volume/network.
Live evaluation must use coordinator-controlled serial authorization and fresh
fixture volumes; never copy a currently owned MTProto session.

## v1.2.1 compatibility, upgrade and rollback

Milestone B changes no completed manifest, encryption envelope, stored chunk
geometry, key/session format or database schema. Legacy-format and recovery
fixtures pass. Milestone A's additive pending queue remains new relative to
v1.2.1; old binaries cannot reconcile active background jobs. A new complete
v1.2.1 ↔ candidate deployment cycle was not executed in Milestone B.

1. Finish or explicitly cancel pending uploads and folder-copy jobs. Confirm final publication and download important files with independent SHA-256 checks.
2. Stop the sole application instance. Produce and verify an encrypted offline backup. Retain its password separately and test restoration into a fresh, nonexistent directory. Telegram content still depends on Telegram availability.
3. Preserve the old image digest, configuration, key, session and original protected volume. Evaluate the candidate using a fresh generated fixture installation before any owner-approved upgrade.
4. For an approved upgrade, use the retained data volume with exactly one running instance. Confirm readiness, authentication, library metadata, ranges and downloaded checksums. Never initialize a bound drive or change its adapter/key/channel to bypass an error.
5. For rollback, stop the candidate first. Do not run v1.2.1 against pending new-queue work. Prefer the verified pre-upgrade backup restored into a fresh volume, plus its matching configuration/image. Newer files created after that backup need an explicit preservation/recovery plan; restoring older metadata does not retain their references automatically.

No upgrade or rollback against the owner's actual volume is authorized/performed
here. Never delete volumes or overwrite the original metadata with a test restore.
Recovery archives omit unfinished parts/cache; missing browser bytes still need
original-file reselection. A revoked Telegram session needs supported QR login.

## Limits and release approval

- Cold preview still fetches/authenticates a whole encrypted chunk. No plaintext derivatives or thumbnail service added. Live PDF/video browser cold/seek latency remains NOT TESTED.
- Cache thrash may add I/O without reducing remote traffic. Cache clears on restart. Native RPC/wire-byte counts were not instrumented.
- Resource results describe one paired 89 s fixture at 768 MiB. Live sustained mixed capacity, multi-hour behavior, sustained four-slot occupancy and hard persistent-disk quotas remain unqualified.
- Remote orphan ownership/count is unknown; no remote cleanup. Actual SIGKILL during maintenance is NOT TESTED; controlled transaction interruption is covered.
- Live cross-DC, actual Safari/iOS, power loss and independent security audit remain NOT TESTED. Telegram account/channel loss is an external durability risk.
- Large native browser downloads lack managed final progress/hash. Mobile transfer panel can cover sidebar controls; close it before navigation/theme changes.

Before any stable release, owner must review these limits and explicitly approve
source push, exact-commit remote CI, version/tag and image publication. Registry
publication and any Dokploy deployment are separate actions. Do not move old
tags, publish an RC through the stable workflow, or assume local checks establish
remote GitHub/GHCR success. No tag is created by this milestone.
