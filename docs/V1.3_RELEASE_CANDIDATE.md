## Candidate contents

remote writes. Accepted, stored and verified states stay distinct. Ciphertext
cache reuses authenticated remote chunks; completion still verifies remote
content directly. Fixes remove a first-cache-miss deadlock and remote-outcome
updates blocked by slow next-part request bodies. No concurrency/chunk-size
increase or unnecessary component rewrite.

`sha256:7ee9bf35716e1497cdb3c250258a84b0526c8cc8fd2ff76f9e05a7f6df2cc11e`.

## Upgrade, rollback and retained risks

Take a verified encrypted offline backup before any owner-approved upgrade.
Do not run an older binary against pending new-queue work; finish/cancel it
before downgrade. Completed file manifests retain their stored geometry.
Recovery archives omit staged parts/cache, so browser source may be needed
after restore. Queued accepted bytes survive process restart; receiving bytes
need commit retry, and final publication still needs `/complete`.

Remote acknowledgement cannot commit atomically with SQLite. Remote orphan
ciphertext and untracked encrypted staging may survive crashes. No automatic
cleanup or hard persistent-volume disk quota is promised. Cold small ranges
still read/authenticate a whole 100 MiB chunk. 768 MiB mixed test reaches its
hard memory limit; production headroom and sustained four-slot stress are not
established. Cache thrashing and native large-download progress limits remain.

Live cross-DC, power loss, live PDF/video playback, physical Safari/iOS,
public-internet deployment and independent security audit remain **NOT TESTED**.
Telegram account/channel loss remains an external durability risk.
