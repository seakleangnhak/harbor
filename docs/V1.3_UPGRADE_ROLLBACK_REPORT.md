original metadata, encryption key, Telegram authorization and release tags remain

## Compatibility contract

Completed files retain the existing AES-256-GCM envelope, chunk identity/AAD,
100 MiB storage geometry, SHA-256 manifests and key/session formats. The durable
background queue added after v1.2.1 is incompatible with an old binary's recovery
logic while work is pending. Rollback uses a verified pre-upgrade archive restored
into a fresh volume; it never starts v1.2.1 against active new queue state.

The test preserves post-upgrade references in a second encrypted archive before
testing the old snapshot. An older snapshot excludes newer files. Operators must
retain the newer installation/archive until those files have an explicit recovery
or export plan; their Telegram messages alone do not reconstruct the library.

  --previous OLD_IMAGE_ID --candidate CANDIDATE_IMAGE_ID \
  --helper HELPER_IMAGE_ID --version 1.3.0 \
  --output output/milestone-c/compatibility-stable

## Owner upgrade and rollback procedure

1. Retain old image digest and matching configuration. Complete or explicitly cancel uploads/copy jobs; confirm queue drain and independently checksum important completed files.
2. Stop the sole Harbor instance. Create and verify an encrypted offline archive; keep its password separately. Test a fresh restore before touching the installation.
3. After separate deployment approval, start the candidate with the same protected volume, encryption key, adapter and channel. Never initialize a bound drive to bypass an identity error. Confirm readiness, login, folders, full checksums, ranges, a new upload and backup.
4. Before rollback, finish or cancel new jobs and confirm queue drain. Stop the candidate, then preserve all newer references in a verified offline post-upgrade archive. Keep that installation/archive protected.
5. Restore the pre-upgrade archive into a fresh volume using matching old configuration/image. Verify old files and session reconnect. Do not overwrite the candidate metadata or run both copies of its authorization concurrently.
6. Retain both archives and newer references until recovery/export of post-snapshot files is settled. Do not delete original volumes or Telegram messages as part of rollback.

HTTP sessions are revoked by default on restore; owner logs in again. Revoked
Telegram authorization requires supported local/HTTPS QR login. Telegram account,
channel and provider availability remain external dependencies. Physical power
loss, live cross-datacenter retrieval and owner deployment upgrade are not covered.
